# 文脈・美的構成・トレードオフ

## 見るべき情報

| 軸 | 判断の問い | ありがちな失敗 |
|---|---|---|
| 主目的 | 何をできれば成功か。速さ・理解・楽しさ・安全のどれが重要か | クリック数や滞在時間を無条件に最大化 |
| 人と状況 | 初心者/熟練者、頻度、疲労、入力と支援技術の違いは何か | 年齢・業種から能力や好みを決める |
| 内容 | 実文章、比較対象、優先順位、量、変動状態は何か | ダミーの短文だけで決める |
| 温度感 | 落ち着き、親しみ、信頼、創作性、没入など何を伝えるか | 色相・彩度だけで感情を決める |
| 密度 | 同時比較が要る領域と、段階表示できる領域はどこか | 全画面を一律コンパクトまたは大きく広くする |
| 重大性 | 間違えたとき何を失い、Undo/復旧できるか | ブランドの雰囲気で安全性を決める |
| 既存の制約 | 変更範囲、デザインシステム、慣習、技術・アクセシビリティ | 独創性の名目で既存の一貫性を壊す |

## 構成を作る（視覚がある場合）

1. ユーザーが最初に知る・行うべき**主役**を1つ明確にする。頻用作業と情緒的な主役は異なり得る。
2. 全体の**情報配置**を選ぶ。例：作業領域中心＋補助レール、概要→詳細、連続したリスト、空間パレット。**カードやサイドバーは必須ではない**。
3. 階層を位置・文字・対比・整列・余白・色/形・質感で組む。共通の操作を一貫させ、必要なところにだけ違いを作る。
4. 無個性な均一配置を避け、主役/周辺、静/動、密/疎の**リズム**を検討する。ただし特徴を入れること自体をノルマにしない。
5. 本物の内容、長文、空、失敗、混雑した状態でも成立するか確認する。

音声・触覚主体のUIでは「視覚階層」を強制しない。順序、発話量、間、繰り返し、聞き直し、確認、触覚フィードバックに置き換える。

## 迷ったときのミニ判断

**価値→選択肢→副作用→検証**の順。大きな新規設計なら2案を比べる。小さな修正は現在案と修正案の比較で十分。

- 余白 ↔ 比較効率：比較の多い部分だけ密度を上げる選択肢がある。
- 個性 ↔ 一貫性：操作は安定、世界観や強調に個性を与えられる。
- 熟練効率 ↔ 初見の発見：安定配置、ヘルプ、ショートカット、段階表示を組み合わせる。
- 注意喚起 ↔ 警告疲れ：危険度・頻度・復元可能性に応じる。
- 視覚表現 ↔ 可読性：意味ある演出を残しつつ、実際の操作・理解を妨げない。

**例:** 高密度のプロジェクト管理画面でも、主役となる情報とブランドを表現する構図は必要。作品鑑賞用の画面では表現を強くできるが、完全削除時は結果と回復可能性を明確にする。
